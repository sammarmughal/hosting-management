# 12 — Design Direction (visual quality bar)

This file sets the **look and feel**. `06-UI-SPEC.md` defines *what* is on each screen. This file defines *how it should look*. If the two conflict on a visual detail, **this file wins**. On behaviour and content, `06` wins.

The goal: the app should look like it was built by an experienced product designer and front-end engineer at a serious SaaS company, not generated by AI. Reference products for tone: **Linear, Stripe Dashboard, Vercel Dashboard, Resend, Height**. They are calm, precise and data-first, with no decoration for its own sake.

---

## 1. Personality

- **Calm operations tool.** The owner opens it to answer one question: *who do I need to chase this week?* Everything serves that.
- **Neutral first, colour with meaning.** About 90% of the UI is neutral greys. Colour appears only for status (green, orange, red, expired), the primary action and focus.
- **Quiet confidence.** Small, precise type, hairline borders, generous but consistent whitespace, and aligned edges.
- **Dense where it matters.** Tables and queues show a lot of information without feeling cramped. Marketing-style spacing does not belong in an admin tool.

## 2. Typography

- Font: **Geist Sans** for UI and **Geist Mono** for timers, amounts and codes (the `geist` npm package, loaded through `next/font` and self-hosted, so no runtime CDN).
- Scale (px): 12 · 13 · **14 (base)** · 16 · 18 · 22 · 28. Most of the UI is 13–14.
- Page title: 22/28, weight 600, letter-spacing −0.01em. **No huge headings.**
- Section/card title: 14, weight 600.
- Labels and meta text: 12–13, `ink-muted`.
- Weights: 400 and 500 for most text, and 600 for titles only. Avoid 700+ except for the big stat numbers (600 is fine there too).
- **All numbers use `tabular-nums`**, and money is right-aligned in tables.
- Sentence case everywhere ("Send all emails", not "Send All Emails"). Use no ALL CAPS, except tiny table headers at 11–12 px with +0.04em tracking, if at all.

## 3. Colour

Keep the tokens from `06-UI-SPEC.md` §1, but use them with restraint:

| Use | Colour |
|-----|--------|
| Page background | `#F7F8FA` (very light cool grey) |
| Surfaces (cards, tables) | `#FFFFFF` |
| Borders / dividers | `#E6E8EC` (1px hairlines) |
| Primary text | `#111827`-ish (`--ink`) |
| Secondary text | `#6B7280`-ish (`--ink-muted`) |
| Primary action / links / focus | brand `#1F4E79` (hover `#173D5F`), focus ring `#2E75B6` at 40% |
| Sidebar | **light**: white or `#FBFBFC` with a right border, and the active item gets a light grey fill + brand text. (A dark navy sidebar reads as a "template". Avoid it.) |
| Status | green, orange, red and expired **only** for status dots, pills, and the left border of queue rows |

Rules:
- **No gradients** (backgrounds, buttons or text). No glows, no glassmorphism, no blurred blobs.
- **No purple/indigo** accents (the default "AI app" look).
- Status backgrounds are very light tints (`*-bg`), and status text is the darker shade. Never use a full-saturation fill behind large areas.
- The big numbers on stat cards are in **ink colour**. Status is shown with a small coloured dot next to the label, not by colouring the number.

## 4. Space, shape, depth

- A 4 px grid. Page padding is 32 px desktop, 24 px tablet and 16 px mobile. Card padding is 20 px (16 on mobile). The gap between sections is 24 px.
- Radius: **8 px** for cards, dialogs and tables, **6 px** for inputs and buttons, and full for pills and avatars. Don't use `rounded-2xl`/`3xl`.
- **Borders over shadows.** Cards are `border` + no shadow (or `shadow-xs` at most). Real shadows are only for floating layers (dropdowns, popovers, dialogs, toasts).
- Content max width is 1200–1280 px, left-aligned inside the main area (not centred with big empty sides on wide screens).
- Everything aligns to the same left edge: page title, cards, table first column.

## 5. Components: how "professional" looks

**Buttons**
- Height 36 px (32 for `sm`), padding 0 14 px, 14 px text, weight 500.
- One primary button per view area. Secondary actions are `outline` or `ghost`.
- Icons in buttons are 16 px, with a 6 px gap. Icon + text only when the icon adds meaning (Send, WhatsApp, Plus). Not on every button.
- Button labels are verbs and specific: "Send 5 emails", "Renew until 30 Sep 2027", "Add client". Never "Submit" or "OK".

**Tables**
- Row height 48 px (desktop). The header row is 36 px, `ink-muted` 12 px, weight 500, with a bottom border.
- **No zebra stripes, no vertical borders.** Horizontal hairlines only, and a subtle hover background (`#F9FAFB`).
- Text columns are left-aligned. **Numbers and money are right-aligned.** The timer column is right-aligned or fixed-width.
- The client cell has two lines: the name (14, 500) with the company or email below (12, muted). Long values truncate with an ellipsis, and the full value shows in a `title` tooltip.
- The row is clickable (goes to the detail page). Row actions sit in a trailing `⋯` menu that is visible on hover and always visible on touch devices.
- A sticky header on long lists. Pagination at the bottom right: "1–25 of 124" with prev/next.

**Timer pill**
- Height 24 px, 12 px mono text, a 6 px status dot, a light tinted background, and **no border**.
- Fixed min-width so that columns don't jitter while ticking.
- The red pulse is a subtle 2 s opacity pulse on the **dot only**, never on the whole pill.

**Status badge:** dot + text ("Urgent"), in the same style family as the timer pill, but not monospaced.

**Stat cards:** label (13, muted, with a status dot) → value (28, 600, ink, tabular) → optional sub-line (12, muted). No icons in coloured circles and no fake sparklines. The whole card is a link, with a subtle hover border colour change.

**Forms**
- Labels 13/500 above inputs. Input height 36 px, 1px border, and on focus a brand border + 3 px soft ring.
- Group related fields in sections with a small section title and a one-line description on the left (desktop two-column "settings" layout: description left 1/3, fields right 2/3). Single column on mobile.
- On mobile, a sticky bottom action bar for Save/Cancel on long forms.
- Inline validation on blur and on submit, with messages in 12 px red below the field.

**Dialogs:** width 480 px (560 for renew), title 16/600, description 13 muted, the footer right-aligned with Cancel (outline) + Primary. A full-height bottom sheet on mobile.

**Toasts (sonner):** bottom-right on desktop, top on mobile, short copy ("Email sent to Ali Khan"), with an Undo action where it makes sense (skip reminder).

**Empty states:** a small line icon (24 px, muted), one sentence, one button. No big illustrations and no emoji.

**Loading:** skeletons that match the real layout (table rows, stat cards). Never a full-page spinner. Buttons show an inline spinner while their action runs.

## 6. Copy and content

- Tone: plain, specific, human. "3 renewals need attention this week", not "You have some items!".
- **No emoji anywhere in the UI** (this overrides the emoji shown in the mock layouts in `06-UI-SPEC.md`). Use lucide icons instead.
- No "Welcome back 👋", no exclamation marks, no "Oops!".
- Dates: `30 Sep 2026`. Relative time where it helps ("2 hours ago"), with the absolute date in a tooltip.
- Money: `PKR 6,500` (no decimals when .00).
- Page titles in the browser tab: `Clients · Renewals`, `Dashboard · Renewals`.

**Mock data must look real** (`src/lib/mock/data.ts`):
- Pakistani client and business names, with a mix of individuals and companies (e.g. "Ayesha Siddiqui", "Karachi Auto Parts", "Bilal Traders", "Noor Dental Clinic", "Al-Madina Textiles (Pvt) Ltd"). Include one very long name to test truncation.
- Realistic domains (`noordental.pk`, `bilaltraders.com`, `almadinatextiles.com.pk`), realistic amounts (PKR 4,500 to 25,000, not round every time), phone numbers in the `03xx` format, and a couple of clients with no email or no phone.
- **Never** use "John Doe", "Lorem ipsum", "example.com", "Test Client" or "Acme".

## 7. Motion

- 150–200 ms, `ease-out`, and only `opacity`/`transform`. Dialogs fade + scale from 98%. Dropdowns fade + 4 px slide.
- No bounce, no spring, no stagger animations on page load.
- Respect `prefers-reduced-motion` (no pulse, instant transitions).

## 8. Details that signal craft (do these)

- Keyboard: `/` focuses search, `N` opens "Add client" (when not typing), `Esc` closes dialogs. Show the shortcut hint in the search placeholder ("Search clients…  /").
- Hover states on every interactive element, and a visible `focus-visible` ring (never `outline: none` without a replacement).
- Cursor `pointer` only on real clickables.
- Consistent icon size (16 px in UI, 18 px in nav) and stroke width (1.75).
- Truncation + tooltip instead of wrapping in table cells.
- Disabled buttons explain why (a tooltip: "No valid WhatsApp number").
- Sidebar: small logo mark + product name "Renewals", nav items 36 px tall with 18 px icons, a count badge on Reminders (a muted pill, not red, unless something is overdue), and the admin name + logout at the bottom.
- A favicon and a proper `<title>` per page.
- Custom `::selection` colour (brand at 15%).
- The layout never shifts when the timer text changes (fixed widths, tabular numbers).
- Mobile: bottom nav 56 px with labels, safe-area insets on iOS, 44 px minimum touch targets, and no horizontal page scroll at 360 px.

## 9. "Looks AI-generated" — never do these

- Gradient backgrounds, gradient text, glowing borders, glass cards, or purple/indigo themes
- Emoji in headings, buttons, empty states or toasts. No "✨" and no "🚀"
- Every stat card with a big icon in a coloured circle
- `rounded-2xl` + `shadow-lg` on every card
- Everything centred, or giant hero headings inside an admin app
- Random decorative charts with meaningless data
- Too many badges and colours on one screen, or rainbow status chips
- Generic copy ("Manage your clients efficiently!") and placeholder names
- Inconsistent spacing (mixing 10/14/18 px); stick to the 4 px grid
- Three different button styles in one row, or icon-only buttons without tooltips
- Centred table text, zebra stripes plus borders plus shadows all together
- Bold everywhere, or ALL CAPS labels everywhere

## 10. Review checklist (run after every screen)

- [ ] Screenshot at **390 px** and **1440 px**, and compare against this file.
- [ ] The only colours visible are neutrals, brand, and status where it has meaning.
- [ ] Every edge lines up, spacing is on the 4 px grid, and there are no orphan paddings.
- [ ] Numbers are right-aligned and tabular, and timers don't jitter.
- [ ] No emoji, no gradients, no placeholder names.
- [ ] Loading, empty and error states exist for every list.
- [ ] Keyboard: Tab through the page, focus is always visible, and Esc closes overlays.
- [ ] No horizontal scroll at 360 px, and touch targets are ≥ 44 px on mobile.
- [ ] `npm run lint` and `npm run build` pass, with no console errors and no hydration warnings.
